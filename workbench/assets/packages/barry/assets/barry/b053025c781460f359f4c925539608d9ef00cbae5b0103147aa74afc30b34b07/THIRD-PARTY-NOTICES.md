## Dependencies and toolchains

Cargo, Python, Maven and npm dependency metadata is not a license for those packages. Redistributors must preserve the actual applicable license texts and notices of linked/bundled dependencies, including Rust standard/compiler libraries, JNI/Wasm support and any bundled native toolchain runtime. Build outputs collect the authenticated dependency notice closure; this summary is not a replacement for it. Source archives exclude installed toolchains, `node_modules`, caches, environments and generated build products.

**All 15 generated families use developer-only zint-bindings 1.2.2 (Apache-2.0), which bundles libzint 2.15.0 (BSD-3-Clause).** The binding wheel installs through `.[dev]` and retains its upstream grants/notices; the installed native bytes are authenticated for generation. No separate Zint CLI/source provisioning is required. Neither the binding nor its bundled library is included in Barry's source or runtime library; redistribution of either remains subject to its own license, not the Barry MIT grant. See the [binding distribution](https://pypi.org/project/zint-bindings/1.2.2/) and [libzint upstream](https://github.com/zint/zint).

**psutil7.2.2 is a Darwin-only developer/test prerequisite, BSD-3-Clause.**
It supplies real process-ownership observations, not barcode recognition. Its
installed Python distribution retains the upstream BSD copyright/grant; prepared
runtime inventories bind that notice and actual package/native-extension bytes.
It is not bundled in Barry's source or recognition library merely because the
test tool uses it, and the Barry MIT grant does not relicense it.

**Qt/PySide and codecs are not MIT Barry code.** The GUI sample source is MIT, but a frozen GUI contains separately licensed shared libraries/plugins. Only the required component closure may ship; GPL-only/unknown components or incompatible codec configurations block that product's distribution. Applicable LGPL obligations include the required notices and corresponding library source/modifications, a usable replacement/relinking route, necessary installation information, and no restriction on permitted debugging/reverse engineering for those modifications. Merely copying license texts does not satisfy all these obligations. See [GUI distribution instructions](docs/gui-distribution.md) for component audit and replacement/source requirements for the actual frozen product.

## Unresolved Apple declaration provenance

SDK-free macOS linking uses interface declarations shipped with Zig0.14.1 and cargo-zigbuild0.20.1. Zig's `lib/libc/darwin/libSystem.tbd` was last updated by [a68119f8](https://github.com/ziglang/zig/commit/a68119f8f1d54b70e713e1e8ce07491ddba0f093), “macos: vendored libc: bump to SDK15.1”; that file has no inline grant. Cargo-zigbuild additionally embeds and caches [iconv/charset stubs](https://github.com/rust-cross/cargo-zigbuild/tree/v0.20.1/src/macos) without separate inline grants. Individual Darwin headers retain their own Apple/Berkeley notices. These installed tools, headers, declarations and caches are excluded from Barry's source export and are not relicensed MIT. Their path-specific redistribution basis remains unlocated in the inspected primary sources. This is distinct from compiled Barry component licensing: importing operating-system symbols or retaining unresolved static system references does not itself distribute the system implementations or complete stub texts.
